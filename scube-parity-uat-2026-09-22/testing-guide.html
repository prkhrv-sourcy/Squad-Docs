0. Set up once

1. Quote pricing

Use SR P, Bulk, one selected product. Restore this baseline before each case unless a step says otherwise. Keep pricing in calculated mode; a target-total override changes the expected numbers.

  1. Enter the baseline. Open quotation shipping/pricing and note physical volume, billed sea CBM and base freight.
  2. Run each row below separately: edit packing, save, reopen the builder and record results. Keep quantity and units/carton at 100.
  3. Finish by restoring 0.4 CBM and 100 kg.
Pass only if: Every row matches. Physical volume stays the entered value; the 1 CBM minimum applies to the whole shipment, not to each product.

P2 · BNPL and QC arithmetic

  1. At baseline, preview the quote and record its total.
  2. In the margin step, set QC cost (USD, once per delivery choice) to 20. Keep ordinary payment terms; record the total.
  3. Select BNPL — 60 Days — Philippines (+3.62%). Record product and delivery prices and total.
  4. Switch BNPL off, then QC back to 0. Confirm the original total returns.
Pass only if: Baseline USD 410.00 → QC only USD 430.00 → QC + BNPL USD 445.71 → baseline USD 410.00. BNPL product unit = 3.11, product total = 311.00, delivery = 134.71. QC is added after logistics markup and before BNPL; multiplying the final 430 by 1.0362 gives a different result because product units round first.

Evidence: Save screenshots of the input values and resulting screen.

P3 · Sea and Land do not charge each other

  1. Restore baseline; set QC to 20 and leave BNPL off.
  2. Choose Sea and Land in shipping. Set Sea last-mile to USD 25 and Land last-mile to USD 10. Land rate must be USD 50/shipment.
  3. Preview both delivery choices. Remove Land, then select it again. Set Sea last-mile to 0 and preview again.
  4. Restore Sea last-mile to 25. Record both choice totals for comparison with the published document later.
Pass only if: Separate alternatives: Sea USD 457.50 and Land USD 386.00. Removing Land does not change Sea. Setting Sea last-mile to zero changes Sea to USD 430.00; Land stays USD 386.00. No combined Sea + Land total or duplicated last-mile/QC charges.

Evidence: Save screenshots of the input values and resulting screen.

P4 · FOB and invalid input

  1. Restore baseline; add QC 20 and BNPL. Switch shipping from DDP to FOB and preview.
  2. Switch back to DDP and reselect Sea. Try QC −1, then restore QC 20.
  3. Clear the product’s packing volume/dimensions, save and try to publish a CBM-based Sea quote. Restore packing afterwards.
Pass only if: FOB total is USD 311.00: goods + inbound + BNPL; no outbound freight or QC. Negative QC is rejected or normalized to a valid value, never saved as negative. Missing packing prevents publication with an actionable message.

Evidence: Save screenshots of the input values and resulting screen.

P5 · Shipment minimum is not charged per product

  1. On a separate copy of P, prepare two selected, validated products. Each has 100 pieces, 100 pieces/carton, 100 kg/carton and 0.4 CBM/carton.
  2. Use only the baseline Sea rate; no last-mile/customs/external costs. Open shipping totals.
Pass only if: Physical shipment is 0.8 CBM / 200 kg. Billed sea volume is 1 CBM and base freight USD 100, not USD 200.

Evidence: Save screenshots of the input values and resulting screen.

2. Stages and sample rounds

Use SR V. Write down each stage’s values before moving to another stage. A new stage starts as a copy of saved values; it is not expected to start empty.

V1 · Keep four different sets of product facts

  1. Select Initial. Set product spec/note to “UAT Initial”, quantity 100, supplier unit price USD 2. Save and reload.
  2. Select Sample round 1. Set spec/note “UAT Sample 1”, quantity 2, price USD 5. Save and reload.
  3. Click New sample round and confirm. Check it copied the latest saved sample. Change spec/note to “UAT Sample 2”, quantity 3, price USD 7; save.
  4. Select Bulk. Set spec/note “UAT Bulk”, quantity 500, price USD 1.80; save.
  5. Revisit Initial, Sample 1, Sample 2 and Bulk, reloading each. Compare product selection, specs, quantity, price and terms with your notes.
Pass only if: All four restore their own saved data. Sample 2 initially copies Sample 1; edits to Sample 2 never overwrite Sample 1 or Initial. It needs fresh final review before sending.

Evidence: Save screenshots of the input values and resulting screen.

V2 · Separate round IDs; revisions stay with their round

  1. Complete product validation and required shipping/terms for Sample 1, Sample 2 and Bulk. Publish each using the confirmation steps in R1; use only the supplied test recipient.
  2. In Quotation, record stage, round, revision, document link and quotation ID for each. Ask the test lead to read the exact ID if not visible in the document link.
  3. Change Sample 1 price, save and publish again. Reopen its earlier version, Sample 2 and Bulk.
  4. Open Invoices and inspect Quotation to invoice. Compare round/revision and totals with the saved documents.
Pass only if: Sample 1, Sample 2 and Bulk have distinct quotation IDs even if their revision numbers match. Republishing Sample 1 increments its own history. Old documents and other rounds retain their earlier facts. Invoice choices identify the correct round and revision.

Evidence: Save one screenshot/document per version and an ID → round → revision → total mapping.

V3 · Separate Sheets and stale browser tabs

  1. On Sample 1, create/open its Google Sheet from the worksheet panel; record the link. Repeat for Sample 2 and compare.
  2. With Sample 2 active, change a recognizable spec in the inactive Sample 1 Sheet. Sync/reload Sample 2; inspect it. Switch back to Sample 1, sync and inspect it.
  3. Open Sample 1 in browser tabs A and B. In A switch to Sample 2. Without reloading B, try to save a changed value in B.
  4. Reload both tabs and inspect each round. Restore the test spec if needed.
Pass only if: Sheet links differ. Sample 1 Sheet edits do not alter Sample 2; they import when Sample 1 is active. A stale-tab save is rejected with a reload instruction, and does not write into Sample 2.

Evidence: Save both Sheet links, before/after values and the stale-save message. Without Sheets access mark the Sheet portion Blocked.

3. Manual review and customer send

R1 · Publication requires a final human confirmation

  1. On a valid quote, reach preview. Compare products, quantities, prices, delivery choices, currency, billing entity and terms with the saved inputs.
  2. Click Publish and send. In the confirmation dialog click Cancel. Inspect quotation history and the test inbox.
  3. Open the dialog again. Click Publish and send quotation once. Save the published document and compare it with preview.
Pass only if: Cancel creates no version and sends no message. Confirm creates the reviewed version and starts sending. Published values match preview. This is a final confirmation, not a separate manager-approval workflow.

Evidence: Save screenshots of the input values and resulting screen.

H1 · Brain sends the exact published quotation

  1. Use the publication from R1. Record its quotation ID, revision and publication time.
  2. Within the test lead’s agreed delivery window, check both the displayed delivery result and the test customer inbox. Open the received quote link.
  3. Ask the test lead to match the notification-history entry to the recorded quotation ID. Compare its document with the published one.
Pass only if: The recipient receives the reviewed quote, linked to the exact published ID. A successful publication alone is insufficient evidence of delivery.

Evidence: Save UI result, received message with time and recipient, notification entry and matching quotation ID. If delivery cannot be observed, mark Blocked.

4. Invoices, addresses and billing

Use the published versions from V2. Save a copy of each source quote before invoicing. Use P’s calculated quote as an additional pricing comparison if needed.

I1 · Invoice the published values, not the current draft

  1. Open an uninvoiced published Sample/Bulk quote and record every item’s description, quantity, unit price, line total, adjustments, currency and grand total.
  2. Change its working draft quantity/price without republishing. Open Invoices and select the original published round/revision.
  3. Select Bill to address A and Ship to address B. Review Billing entity and payment account. Click Generate proforma.
  4. Open the new invoice, then its printable document. Compare every recorded field and add line totals plus listed adjustments.
Pass only if: Invoice matches the selected published quote, not draft edits. Line totals plus adjustments equal the grand total in its currency. No real priced product becomes quantity 1 × USD 0. No delivery choice is added a second time.

Evidence: Save source quote and invoice/PDF side by side with a line-by-line reconciliation. Do not recompute totals from a visually shortened unit price when the published quote retains more precision.

I2 · Eligibility and duplicate prevention

  1. On an SR with only an Initial quote or an unpublished Sample draft, open Invoices.
  2. Publish a valid Sample quote using R1; return to Invoices and generate its proforma after selecting addresses.
  3. Reload. Try to select the same exact quote for another invoice.
  4. On this unpaid test invoice, use its void action and confirm. Reload the eligible quote list.
Pass only if: Initial and unpublished drafts cannot be invoiced. Published valid Sample/Bulk versions can. A quote with a non-void invoice is not offered again. Voiding the unpaid test invoice restores its eligibility; the old voided record remains.

Evidence: Save screenshots of the input values and resulting screen.

I3 · Same revision number must not mix Sample and Bulk

  1. From V2, choose a Sample and a Bulk version with the same revision number but different IDs and totals. If unavailable, have the lead prepare this fixture.
  2. Generate an invoice from each exact selector entry, choosing addresses each time.
  3. Open both invoices after switching the current draft between Sample and Bulk.
Pass only if: Each invoice keeps its intended stage, quantity and price. Identical revision numbers never cause one quotation’s contents to replace the other’s.

Evidence: Record both quotation IDs, shared revision number and corresponding invoice IDs.

B1 · Correct seller, bank and separate customer addresses

  1. In quote builder terms, choose the test lead’s approved billing entity and supported quote currency. Publish a fresh valid version.
  2. In Invoices, select that version; choose A for Bill to and B for Ship to. Compare the automatically displayed seller/address/payment instructions with the independent Finance reference.
  3. Generate and open the invoice. Compare seller, both customer addresses, payment instructions, currency and total again.
  4. Repeat with SG, HK, PH and ID using approved entity/currency pairs. Use a new version or SR for each.
Pass only if: Each new invoice uses the selected quotation’s entity and matching approved payment instructions; non-SG invoices do not silently use SG details. Bill-to A and ship-to B remain distinct. Invoice currency and bank account currency may differ where the approved reference explicitly allows it.

Evidence: Save a comparison per entity. Missing configured entities/currencies are Blocked, not substituted.

B2 · Missing billing information blocks creation

  1. Select an eligible quote but leave Bill to unselected; then test with Ship to unselected.
  2. Use the supplied test customer with no complete address and inspect invoice creation.
  3. Use the lead-prepared quote with no matching payment profile for its entity/currency. Inspect the message and Generate button.
Pass only if: Generation is blocked until both valid addresses and exactly one matching payment profile exist. A clear address/payment message appears. No fallback bank account or Singapore seller is inserted.

Evidence: Save the blocked control and message for each situation; the lead must prepare missing-data fixtures without changing shared production configuration.

B3 · Issued invoice facts never change

  1. Save a PDF/screenshot of a new invoice from B1 and its invoice ID.
  2. Publish a later quotation revision with a different price/entity. Have the test lead edit the test customer’s address record and approved test payment profile.
  3. Reopen the original invoice and print it again. Compare with the first copy.
  4. Also open one historical invoice without a billing snapshot, supplied by the test lead.
Pass only if: The new invoice retains its original seller, addresses, payment instructions, quantities and amounts. Payment/void status may change separately. Historical unsnapshotted invoices may retain the old SG template; their exact old quote must render, or an unavailable-source error must appear—never current pricing.

Evidence: Save before/after documents. Record the historical-template exception separately; it is not evidence that new billing is broken.

5. SR editing, closure and reordering

E1 · Edit brief and delivery address

  1. Open manual SR E → Edit request. Change Customer brief / notes to “UAT edited brief” and choose address B → Save changes.
  2. Reload and reopen Edit request. Check both values. Open a product’s review page; change quantity/specification, save and reload it.
  3. Return to quotation builder and review pricing/delivery for the changed request. Compare any previously published document with its saved copy.
Pass only if: Brief/address and item edits persist. Published documents retain their original details. New pricing/delivery is reviewed for the edited request; ordinary saves do not silently publish or notify customers.

Evidence: Save screenshots of the input values and resulting screen.

E2 · Copy selected supplier matches to a new manual SR

  1. Open the supplied source SR → Copy / reorder. In Copy from, keep Current request products.
  2. Choose only one of its two distinguishable items. Set Copy into to New manual SR for this customer → Copy selected items.
  3. Record the new SR number. Check customer, chosen item, specs and supplier reference. Open its product review and attempt quotation preparation before revalidation.
  4. Refresh the source SR. Check both original products remain unchanged. Fill fresh price, stock/MOQ, delivery and validation on the copied item, then use R1.
Pass only if: A new manual SR contains only selected items and reusable references. Supplier prices, MOQ/lead-time approvals and validation are not carried forward as current facts. Quoting needs fresh review. Original SR is unchanged.

Evidence: Save screenshots of the input values and resulting screen.

E3 · Reuse a past order into an existing SR

  1. Open source SR → Copy / reorder → Copy from → choose its past order and one item.
  2. In another tab open the supplied manual target SR, select Sample round 2 and note existing items. In the copy dialog choose Existing SR for this customer and enter that SR number.
  3. Click Copy selected items. Open target and inspect the active round, other rounds and original order.
  4. Try the same copy into the lead’s SR belonging to a different customer; then cancel.
Pass only if: Only selected past-order items are added to the target’s selected round; existing items and other rounds remain intact. Supplier/product references carry over, historical prices and approvals do not. Original order is unchanged. Cross-customer copying is blocked.

Evidence: Save screenshots of the input values and resulting screen.

E4 · Close as lost and preserve history

  1. Run this last on manual SR E. Save its existing quote/invoice links. Click Close request. Leave the reason empty.
  2. Confirm closure is unavailable. Enter “UAT: customer did not proceed” → Close as lost. Reload.
  3. Check the closed/lost state and saved closing reason/history. Try Edit request and quotation publication. Open the saved quotes and invoices.
  4. Use Copy / reorder to copy an item into a new manual SR.
Pass only if: A reason is required. The SR stays closed after reload; editing/new publication is blocked. Existing documents remain accessible. Copying can start a separate manual SR without reopening or changing the closed source.

Evidence: Save screenshots of the input values and resulting screen.

E5 · Brain-controlled requests are guarded

  1. Open the supplied Brain-controlled SR. Try Edit request and Close request.
  2. Try copying an item into that SR as an existing target. Inspect the explanation.
  3. If the lead supplies an SR whose Brain state cannot be confirmed, repeat there.
Pass only if: These mutations are blocked with a Brain stop-work/state explanation. The source request remains unchanged. This is an intentional current limitation, not proof of completed ownership handoff.

Evidence: Save screenshots of the input values and resulting screen.

6. Assisted cases — still required

The test lead/engineer prepares each condition and records service-side evidence. Product follows the browser steps and checks the outcome. Do not manipulate databases or disable shared services to create these conditions.

H2 · Send failure, retry and uncertain delivery Test lead / engineer assisted

  1. Engineer configures a test-only Brain send failure before delivery; Product publishes a valid quote. Record its ID/revision and the warning.
  2. Engineer restores delivery. Product uses Send to customer on that version (or Retry sending in the warning).
  3. Engineer verifies notification history and recipient count. Separately simulate an ambiguous timeout/duplicate acknowledgement and inspect the result before retrying.
Pass only if: Failed send preserves the published quote. Retrying uses the same ID/revision, without creating another version or duplicate customer message. Uncertain acknowledgement remains pending/uncertain until history establishes delivery; it is not reported as confirmed sent.

Evidence: Save published ID/revision before/after, failure/pending UI, notification-history IDs and received-message count.

H3 · Takeover, handback and agent suppression — known gap Test lead / engineer assisted

  1. Engineer prepares an active Brain test SR and a harmless scheduled agent action; record the next action time and Brain ownership state.
  2. Product uses the SR takeover control, if available. Record actor/time. Engineer checks Brain ownership, lets the scheduled action become due, and checks actual action/message history. Product checks the test customer’s ownership notification.
  3. Product uses handback/release if available. Engineer checks Brain ownership and that a newly scheduled action can proceed once. Product checks the configured handback notification.
  4. If controls or integration are absent, record the missing part. Do not mark Pass because Squad says “agents are paused”.
Pass only if: Target acceptance: Brain records human ownership, suppresses due autonomous work while held, receives handback and resumes appropriate work without duplicate notifications; the customer gets required ownership updates. Current evidence: this integration is explicitly deferred; the local takeover writes Squad ownership/ledger only. Treat this requirement as open until service evidence proves it.

Evidence: Record Brain state transitions, due-action outcome and customer notifications. Mark Fail for observed continued action; Blocked for absent integration or unavailable observation.

A1 · Invalid invoice data and exact-ID enforcement Test lead / engineer assisted

  1. Engineer provides isolated published-quote fixtures: missing priced rows, currency/total mismatch, unavailable exact source, and Sample/Bulk sharing revision 1.
  2. Product attempts invoice creation for exposed fixtures. Engineer also submits an invoice request with only the ambiguous revision and one with an address owned by another customer.
  3. Inspect the UI/API error and invoice list after each attempt.
Pass only if: Bad pricing, ambiguous identity, unavailable source and foreign-customer addresses are rejected. No fabricated quantity 1 × 0 lines, substituted current quote or partial invoice is created.

Evidence: Attach fixture ID, submitted case, error and confirmation that no invoice was created. Engineer owns API-only attempts.

A2 · A stale edit cannot overwrite a newer one Test lead / engineer assisted

  1. Open manual SR E (or another still-open manual SR) in two tabs. Open Edit request in both before saving either.
  2. In A change notes and save. In B change notes differently and save without reloading.
  3. Reload and inspect the notes. Repeat quotation publication from an old preview after editing the request in another tab.
Pass only if: Stale edit is rejected and A’s saved data remains. Stale publication requires reloading/reviewing the changed request; no old-address or old-price quote is silently sent.

Evidence: Save stale-save/publish messages and final persisted values.
