Google Sheets in Squad

Review many product options in a familiar spreadsheet, bring the edits back into Squad, and build a quotation for a chosen final amount.

Feature guide + end-to-end test steps · 15 September 2026

How it worksWhat you can doBefore testingA. Sourced itemsB. Vendor documentsFinish the quoteExtra checks

One review flow. Two ways to start.

A. Existing sourced items

Start with products already on a sourcing request (SR). Create a Google Sheet to review them in bulk.

B. Vendor documents

Upload an invoice, purchase order or spreadsheet. Squad extracts product details so you can create a manual SR and review the products.

The most important rule: Editing the sheet does not update Squad automatically. Squad refreshes the change preview; you click Import reviewed changes to apply it. Changed items must then be validated in Squad.

What the feature can do

Sheet tabWhat you can review or change
ItemsDescription, Include, quantity, unit price, original currency, MOQ and lead time.
Price breaksChoose one price break per item. Its price and minimum quantity are used together.
ChargesEdit existing add-ons, fees and inbound values. Reference currencies and units stay fixed.
SpecificationsEdit requirements and review results. Explain partial matches or mismatches.
DocumentsEdit existing attachment details and image links. Source evidence stays read-only.
Packing & samplesEdit dimensions, weights and sample details. Estimated measurements stay labelled estimated.
Settings / Quote totalsSettings holds guidance and reference values. Set settlement currency in Squad. Quote totals is protected calculated output.

Target total: Enter the final customer-payable amount. Squad calculates product markup using its quotation pricing and exchange rates, includes applicable fees, tax and discounts, and shows any rounding adjustment.

Built-in checks: Conflicting edits are blocked. Changed items need another validation. Stale calculations cannot be finalized or published as if they were current.

Current boundaries: Edit existing rows in the sheet; add or remove product options in Squad. Do not rename columns, change hidden IDs, enter formulas or edit protected output. Sheet output is a saved calculation, not a live approval status. Settlement currency is selected in Squad.

Before you test

  • Confirm the PR has deployed successfully to dev.squad.sourcy.ai. This guide is a test plan, not confirmation that live acceptance has passed.
  • Sign into Squad with your employee account and Google with a Growth account that can edit the workbook.
  • Use a dedicated test customer and SR. Record the SR number and sheet link.
  • For path A, choose an SR with at least two product options. For the price-break test, include an item with existing quantity tiers.
  • For path B, have a test vendor file and a test delivery address ready.

File limits: 1–5 files; 10 MB per file; 25 MB combined. Supported: PDF, PNG, JPEG, WebP, CSV, TXT and XLSX. Extraction can make mistakes: compare it with the original file.

Test A

Existing sourced items → reviewed quote

  1. Open a test request

    Use an existing dev sourcing request with product options. In Google Sheet review, click Review in Google Sheet.

    Pass: A workbook is created. Open Google Sheet becomes available.

  2. Open and edit the workbook

    Sign into Google with a Growth account. In Items, change one description and one valid unit price. Record the old and new values. Keep the original currency unchanged.

    Pass: Editable cells accept changes. Reference fields remain protected in new workbooks.

  3. Review the changes in Squad

    Return to the request. Wait up to 30 seconds with the page visible, or click Refresh sheet changes. Expand Review changes.

    Pass: The preview shows your old and new values. Reading the sheet alone does not apply the edits.

  4. Import your edits

    Click Import reviewed changes. Check the item in Squad.

    Pass: The new values appear in the quote draft. The changed item needs validation again.

  5. Validate and select

    Open each changed item’s validation page. Review required fields and save its validation. Select the intended options for the quote.

    Pass: All selected options are valid. Unticked alternatives are excluded from the quotation.

  6. Finish the quote test

    Continue with the shared steps below: solve, compare totals and finalize.

    Pass: The target total agrees in Squad and the sheet.

Test B

Vendor file → new SR → reviewed quote

Download sample vendor CSV

Two products · USD 500 source total · fictitious test vendor. A sample passing does not replace a test with your real vendor file.

  1. Start a new request

    Open the new-request page in dev. Click Upload vendor documents. Use the sample CSV linked above first, then repeat with a real vendor file approved for dev testing.

    Pass: Upload is accepted and extraction begins.

  2. Check the extraction

    Wait for extracted products. For the sample, check TEST-001: 100 × USD 2.00, and TEST-002: 200 × USD 1.50. Check warnings, currencies and source evidence.

    Pass: Two product lines appear; their source total is USD 500. Missing or incorrect information is visible for review.

  3. Create the sourcing request

    Choose the test customer, delivery address and owner. Click Create SR once. Extracted rows are read-only here; make corrections in Squad after creation.

    Pass: One SR is created. Vendor mode does not start automated sourcing or supplier outreach.

  4. Open the workbook

    Open the new request and wait for workbook creation. Click Open Google Sheet.

    Pass: Document-backed products and their evidence appear. They are not automatically validated.

  5. Edit, import and validate

    Change one item description or price. Return to Squad → Refresh sheet changes → Import reviewed changes. Correct any missing details, validate and select the products.

    Pass: The edit reaches the correct product. Original document evidence remains available.

  6. Finish the quote test

    Continue with the shared steps below. For vendor cases, check whether No logistics invoiced should remain selected.

    Pass: The final amount includes only the delivery and charges intended for this test.

Shared final steps · for A and B

Solve, finalize and check the quotation

  1. Enter the target

    In Solve for target total, choose settlement currency and the final amount the customer should pay. Enter tax, extra fees and discounts explicitly. Check No logistics invoiced only when freight and inbound charges should be excluded.

    Pass: The target means the final payable amount, not just the product subtotal.

  2. Solve and check both places

    Click Solve and update sheet. Open the protected Quote totals tab. Compare quantities, selling prices, fees, tax, discounts, rounding and final total against Squad.

    Pass: The final total matches the target exactly in the chosen currency. Currency conversion and rounding are shown. An impossible target is rejected.

  3. Finalize

    Click Finalize target quote.

    Pass: Squad shows “Target quote finalized and written to Google Sheet.” Finalizing does not publish or send the quote.

  4. Check the normal quote preview

    Open the normal quote builder using the same selected items. Review the preview without changing the inputs.

    Pass: The selected items and payable breakdown agree with the finalized calculation.

  5. Test publication on a test customer

    For a full publication test, use a dedicated test customer only. Choose Publish without sending and confirm Publish quotation.

    Pass: A quotation revision becomes customer-visible. No notification is sent by this action. Compare its currency and final amount with the finalized target.

Simple example: With the sample’s USD 500 source total unchanged, both products selected, USD settlement, no logistics, and all fees/tax/discounts at zero, try a USD 650 target. Expect the final payable amount to be USD 650. If you changed the input prices, choose a suitable target for the revised costs.

Check the important edge cases

Run these on the test SR. Restore valid values after each test.

TestDo thisExpected result
Change after finalizationChange an item price in the sheet, then import it.The prior calculation/finalization becomes stale. Revalidate the changed item, solve and finalize again before publishing.
Same field edited twiceEdit one description in Squad and the same description differently in the sheet, before importing.Import reports a conflict instead of overwriting either edit. Align the values, refresh and retry.
Unvalidated itemImport a price change and try to prepare or solve the quote before validating that item.The operation is blocked until the selected item is validated.
Two price breaks selectedFor an item with multiple existing price breaks, select two and try importing.Import rejects the selection. Leave exactly one selected and retry.
Invalid inputIn an editable numeric cell, enter text or a formula and try importing.Import rejects it with a useful message. Restore a valid number.
Reload and resumeReload the request after workbook creation. Reopen the workbook.The same SR and workbook are reused; no duplicate is created.
Detailed tabsFor an item with existing supporting rows, edit a spec note, fee label, attachment note and sample value. Refresh, import and inspect Squad.Each supported edit reaches the correct item. Reference values and source evidence stay unchanged.

If something does not work

What you seeWhat to do
Feature disabled or upload unavailableAsk engineering to confirm the dev deployment, feature flag and migrations.
Google access deniedCheck the signed-in Google account and Growth access. Send the workbook link to engineering.
Sheet needs attention / conflictRead the listed cells. Correct the inputs or align the conflicting values, refresh, then import again.
Calculation saved; sheet update incompleteUse Update sheet again. Check Quote totals before finalizing.
Inputs changedRefresh and import pending edits, validate affected items, then solve and finalize again.
Vendor request stuck submittingRecord the intake/SR details and contact engineering. Do not create another SR to work around an uncertain submission.

What to record

Tester and date · SR number · workbook URL · vendor file type · expected and actual result · screenshot of any error. Mark each path Pass / Fail / Not run. Record publication separately if you stopped at preview.

Acceptance is complete when: both paths work, the changed items require validation, totals agree across Squad and Google, protected fields are respected, and the publication check passes on a test customer.
